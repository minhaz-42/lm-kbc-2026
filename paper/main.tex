\begin{abstract}
Large language models (LMs) store a remarkable amount of factual knowledge in
their parameters, yet turning that knowledge into a reliable, \emph{set-valued}
knowledge base---where a subject may have zero, one, or many objects---remains
difficult. The LM-KBC~2026 shared task (5th edition, at the AKBC workshop,
EMNLP~2026) poses exactly this in a strict \emph{closed-book} setting: an
open-weight model of at most 32B parameters, with no retrieval, no external
knowledge, and no fine-tuning. We start from the evaluation metric and observe
that it rewards \emph{abstention}: predicting the empty set for every instance
already scores $0.175$ relation-averaged macro-F\textsubscript{1}, close to the
official baseline ($0.273$). We therefore treat \emph{when to answer} as a
first-class decision and build a per-relation pipeline that (i)~grounds each
prompt in the relation's exact scope, (ii)~induces calibrated abstention by
\emph{self-consistency voting}---abstaining when repeated samples
disagree---rather than by instruction, and (iii)~aggregates numeric relations by
median. With Qwen2.5-14B-Instruct run in 4-bit on a single 16\,GB GPU, the
system reaches $0.416$ relation-averaged macro-F\textsubscript{1} ($0.447$
micro), improving over the official baseline ($0.273$/$0.284$) on five of six
relations, with the largest gains where abstention matters most. All generation
is cached, so the entire decode stage---including the abstention
threshold---is reproducible without a GPU. We release our
code.\footnote{\url{https://github.com/ANON/lm-kbc-2026}}
\end{abstract}

\section{Introduction}
Pre-trained language models (LMs) store a remarkable amount of factual knowledge
in their parameters, acquired during pre-training on large text corpora
\citep{petroni2019lama,roberts2020closedbook}, and a body of work probes and
extracts it \citep{jiang2020lpaqa,zhong2021optiprompt,alkhamissi2022review}.
This raises the prospect of building a structured knowledge base (KB) directly
from an LM rather than from curated sources \citep{dong2014knowledgevault,vrandecic2014wikidata}.
Doing so reliably is harder than answering a single factual question: a KB entry
is a \emph{complete set} of facts, so the model must decide not only what is true
but how many objects---possibly none---a subject and relation admit.

\paragraph{The LM-KBC 2026 task.} The shared task
\citep{alivanistos2022prompting,kalo2023lmkbc,kalo2025lmkbc} formalises this as:
given a subject $s$ and relation $r$, predict the complete object set
$\{o_1,\dots,o_k\}$, where $k$ may be zero, one, or many. Predictions are scored
by macro precision, recall, and F\textsubscript{1}, with string normalisation
and alias matching for entities and a 5\% tolerance for numeric relations. The
2026 edition is strictly \emph{closed-book}: a system may use any open-weight
model up to 32B parameters, but no web search, no retrieval, no external corpus,
and no fine-tuning. This rules out the retrieval and tuning that strong entries
in earlier editions relied on \citep{zhang2023llmke,asai2024selfrag}, leaving
parametric recall and \emph{prompt design} as the only levers.

\paragraph{Why this is hard.} Unlike single-answer probing benchmarks such as
LAMA \citep{petroni2019lama}, which assume exactly one gold object and reward
ranking it highly, this setting demands the \emph{entire} set---and the empty
set is a legitimate, frequent answer (a living person has no recorded city of
death; an island country has no land border). Three difficulties follow. First,
LM outputs are stochastic and prompt-sensitive, so a single query yields
unstable sets. Second, relations span very different cardinalities, from a single
number to hundreds of award recipients, complicating aggregation. Third, the
model must recognise when it does not know an answer and \emph{abstain} rather
than fabricate one.

\paragraph{Our approach.} We start from the evaluation metric itself. Because
macro-F\textsubscript{1} scores an empty prediction against an empty gold set as
perfect, simply predicting nothing everywhere already attains $0.175$
relation-averaged macro-F\textsubscript{1} on validation---competitive with the
official baseline ($0.273$) and better on the most null-heavy relations
(Section~\ref{sec:task}). The lesson is that points come not from answering
everything, but from recalling the few numeric values and, above all, knowing
when \emph{not} to answer. We therefore make abstention a first-class decision:
we sample each null-heavy relation several times and keep an object only when the
samples agree, collapsing to the empty set when the model is internally
inconsistent. Scope-grounded prompts and median aggregation for numeric relations
complete the pipeline (Figure~\ref{fig:pipeline}).

\medskip\noindent Our contributions are:
\begin{enumerate}[noitemsep,topsep=2pt,leftmargin=*]
  \item A metric analysis (Section~\ref{sec:task}) showing that, under the macro
  metric, abstention is a high-value action: the predict-nothing baseline already
  rivals the official baseline, which reframes the task around \emph{when to
  answer}.
  \item A per-relation pipeline (Figure~\ref{fig:pipeline}, Section~\ref{sec:method})
  that grounds prompts in exact scopes and induces \emph{calibrated abstention}
  via self-consistency voting, with no trained confidence model: it lifts a weak
  0.5B model from $0.173$ to $0.372$ on the null-heavy relations and still helps
  a strong 14B.
  \item A reproducible open-weight system on a single 16\,GB GPU reaching
  $0.416$ relation-averaged macro-F\textsubscript{1}, beating the baseline on
  five of six relations, with cached generation enabling GPU-free decode-stage
  tuning (Sections~\ref{sec:setup}--\ref{sec:analysis}).
\end{enumerate}

\section{Background and Related Work}
\paragraph{LMs as knowledge bases.} \citet{petroni2019lama} cast factual recall
as cloze probing; follow-ups sharpened the prompts \citep{jiang2020lpaqa,
shin2020autoprompt,zhong2021optiprompt}, quantified how much knowledge a model's
parameters hold \citep{roberts2020closedbook}, and questioned how reliably it can
be read out \citep{cao2021knowledgeable,alkhamissi2022review}. These probes
assume a single gold object and reward ranking it highly. We instead target the
set-valued, alias-graded variant in which the empty set is a valid answer, which
is closer to materialising an actual KB \citep{pan2023llmkg}.

\paragraph{The LM-KBC shared task.} Across its editions
\citep{alivanistos2022prompting,kalo2023lmkbc,kalo2024lmkbc,kalo2025lmkbc} the
task has moved from masked-LM probing and prompt ensembling toward
instruction-tuned generative systems, with some earlier tracks permitting
retrieval or fine-tuning \citep{zhang2023llmke}. The 2026 edition's closed-book,
no-tuning, $\le$32B rules remove those options---which is precisely what makes a
parametric-recall-plus-abstention design necessary.

\paragraph{Retrieval vs.\ closed book.} The usual route to knowledge-intensive
accuracy is retrieval augmentation \citep{lewis2020rag,guu2020realm}, which helps
most exactly when parametric memory is weak \citep{mallen2023whennot}. Self-RAG
\citep{asai2024selfrag} even lets the model decide \emph{when} to retrieve; we
borrow the spirit of a model-driven, adaptive decision but, with retrieval
forbidden, apply it to a different one---\emph{when to answer at all}, not what to
fetch.

\paragraph{Self-consistency, calibration, and abstention.} These threads converge
in our method. Self-consistency \citep{wang2022selfconsistency,chen2023universalsc}
samples a model repeatedly and aggregates the generations to pick a single
answer. Abstaining when uncertain is the classic reject option
\citep{geifman2017selective}, studied in NLP as calibration
\citep{guo2017calibration}, unanswerable QA \citep{rajpurkar2018squad2}, and
selective QA \citep{cole2023selective}, and LMs retain some awareness of what
they know \citep{kadavath2022know}. We combine the two: cross-sample
\emph{disagreement} \citep{kuhn2023semantic,manakul2023selfcheckgpt} is our
zero-parameter confidence signal, and---unlike majority-vote self-consistency,
which always emits an answer---we let it trigger \emph{abstention}, because here
the empty set is itself a high-value prediction.

\section{Task and Metric Analysis}
\label{sec:task}
\paragraph{Relations.} The dataset comprises six Wikidata relations
(Table~\ref{tab:data}) that fall into three groups. \emph{Numeric} relations
(\textsc{hasCapacity}, \textsc{hasArea}) have a single scalar object;
\emph{large-set} \textsc{awardWonBy} has up to hundreds of recipients per
subject; and three \emph{null-heavy} string relations
(\textsc{countryLandBordersCountry}, \textsc{personHasCityOfDeath},
\textsc{companyTradesAtStockExchange}) leave a large fraction of subjects with no
valid object at all. Each relation carries a precise scope---land-only borders,
city-granular death location, the highest published capacity---which we copy
verbatim into the prompt so the model targets the same notion the gold set was
built against.

\paragraph{Evaluation.} Predictions are scored against the gold object set by
macro precision and recall. A predicted string is a true positive if its
normalised form (lower-cased, diacritics and punctuation removed) matches any
alias of a gold object, and a numeric prediction if it lies within 5\% of the
gold value. Two boundary conventions drive everything that follows: precision is
defined as $1$ when the prediction is empty, and recall as $1$ when the gold set
is empty. We report \emph{relation-averaged} macro-F\textsubscript{1} (the mean
of the six per-relation scores) and \emph{micro-averaged} F\textsubscript{1}
(over all instances).

\paragraph{The metric makes abstention valuable.} Those two conventions make an
empty prediction against an empty gold set a perfect F\textsubscript{1}, with a
large consequence: predicting the empty set for \emph{every} validation instance
already scores the ``Empty'' bars in Figure~\ref{fig:bars}, averaging $0.175$
relation-averaged macro-F\textsubscript{1} ($0.203$ micro). This is on par with
the official baseline's $0.273$ and \emph{above} it on the two most null-heavy
relations (\textsc{personHasCityOfDeath} $0.45$ vs.\ $0.16$;
\textsc{companyTradesAtStockExchange} $0.35$ vs.\ $0.32$). The task therefore
rewards not answering everything, but two narrower abilities: recalling the few
numeric values, and abstaining precisely when no object exists. These are the
levers our pipeline pulls.

\section{System}
\label{sec:method}
\paragraph{Architecture overview.} The pipeline (Figure~\ref{fig:pipeline}) maps
each $(s,r)$ to one chat prompt, decodes $N$ or $n$ cached samples, and aggregates them
per relation kind into an object set. It has no trainable parameters and targets
the two analysis levers: abstention and numeric recall.

\paragraph{Scope-grounded prompts.} Each relation's system message states the
task, the \emph{exact} ground-truth scope (copied from the official definitions),
and the answer shape; the model emits one JSON object
\texttt{\{"answers":[\dots]\}} (Figure~\ref{fig:prompt}). This makes the empty
case unambiguous. Few-shot exemplars come from the training split; for null-heavy
relations we interleave empty and non-empty exemplars so abstention is
demonstrated, not merely instructed. Even a 0.5B model emits valid JSON on 100\% of instances, so format is never a bottleneck.

\paragraph{Calibrated abstention via self-consistency.} Scope grounding tells the model \emph{what} counts as an answer, but not \emph{when} to stay silent. A bare instruction to
``answer empty when unsure'' is unreliable: an unconstrained small model names a
death-city for living people and invents stock exchanges, dropping precision
\emph{below} the empty baseline (Section~\ref{sec:analysis}). Instead, for the
three null-heavy relations we sample $N{=}3$ completions at temperature
$\tau{=}0.7$ and keep an object only if it appears in at least a fraction
$\theta$ of samples; single-object relations abstain entirely if even the top
answer is below $\theta$ (Algorithm~\ref{alg:abstain}). When the model guesses,
samples disagree and the prediction collapses to $\emptyset$---where the metric
rewards silence. This is disabled for \textsc{awardWonBy} (recall-bound) and the
numeric relations.

\begin{algorithm}[t]
\small
\caption{\textsc{CalibratedAbstention}}
\label{alg:abstain}
\begin{algorithmic}[1]
\Require samples $S{=}\{s_1,\dots,s_N\}$, threshold $\theta$, \textit{multi}
\State $c[o] \gets \#\{s_i : o \in \textsc{parse}(s_i)\}$ for each object $o$
\If{\textit{multi}} \Return $\{o : c[o]/N \ge \theta\}$
\Else
  \State $o^* \gets \arg\max_o c[o]$;\ \ \Return $c[o^*]/N \ge \theta \,?\, \{o^*\} : \emptyset$
\EndIf
\end{algorithmic}
\end{algorithm}

\paragraph{Numeric aggregation.} The numeric relations need a different aggregator. \textsc{hasCapacity} and \textsc{hasArea} take a
single number graded within 5\%. We sample $n{=}5$ completions and take the
\emph{median} of the parsed numbers \citep{wang2022selfconsistency} for
robustness.

\paragraph{Robust parsing.} Whatever the relation kind, every sample passes through a common final stage. A relation-aware parser recovers the answer list from
noisy output (code fences, prose), strips explicit empty markers, extracts one
number for numeric relations (handling commas, units, scale words), and
de-duplicates. Normalisation (lower-casing, diacritic/punctuation removal) is
byte-identical to the official evaluator; pushing gold answers back through the
parser scores $1.000$, confirming it is lossless.

\section{Experimental Setup}
\label{sec:setup}
\paragraph{Model.} We use \textbf{Qwen2.5-14B-Instruct} \citep{qwen2024}
(14.7B parameters, within budget). Several nominally ``32B'' models exceed the
cap (Qwen2.5-32B at 32.5B; Qwen3-32B at 32.8B) and are disqualified; 14.7B was
the largest model we could fit in 4-bit on our single 16\,GB GPU.

\paragraph{Inference and reproducibility.} Inference runs on one NVIDIA T4
(16\,GB) via 4-bit \texttt{bitsandbytes} (\texttt{nf4}), \texttt{float16}
compute \citep{dettmers2023qlora}. We use 8-shot prompts
\citep{brown2020gpt3} (2-shot for \textsc{awardWonBy}), with the submitted system fixing
$\theta{=}0.5$, $N{=}3$, $n{=}5$, $\tau{=}0.7$. Generation writes a cache of raw
samples; all post-processing---parsing, voting, median, threshold---is a
deterministic GPU-free function of that cache, so every ablation below comes from
one generation pass, reproducible without a GPU.

\section{Results}
\label{sec:results}
Putting the pipeline together, the system scores \textbf{0.416} relation-averaged macro-F\textsubscript{1}
(\textbf{0.447} micro), versus $0.175$/$0.203$ (empty) and $0.273$/$0.284$
(official baseline)---a same-axis gain on both. Figure~\ref{fig:bars} and
Table~\ref{tab:results} give the per-relation picture: we beat the baseline on
five of six relations, the exception being \textsc{hasCapacity} ($0.09$ vs.\
$0.10$), where exact capacities are essentially unknown to the model. The
strongest relations are \textsc{countryLandBordersCountry} ($0.900$) and
\textsc{companyTradesAtStockExchange} ($0.616$); the high precision on
\textsc{personHasCityOfDeath} ($P{=}0.81$) is the signature of abstention at work.

\section{Analysis}
\label{sec:analysis}
All ablations are decoded from the same cached samples.

\paragraph{Abstention rescues weak models, refines strong ones.}
Table~\ref{tab:ablation} isolates abstention on the three null-heavy relations.
On a poorly-calibrated 0.5B model the effect is dramatic ($0.173\!\to\!0.372$): without voting it over-answers and falls \emph{below} the empty baseline ($0.350$). The 14B is already above empty without voting
($0.652$), so voting adds less ($0.652\!\to\!0.666$) but remains positive.
Abstention buys precision: on \textsc{personHasCityOfDeath} it moves
$P{=}0.77\!\to\!0.81\!\to\!0.89$ as $\theta$ rises, trading a little recall---it
suppresses wrong guesses, not correct answers.

\paragraph{Threshold tracks the empty rate; numeric voting is neutral.}
If abstention is what drives the string relations, the natural question is how its threshold should be set.
Figure~\ref{fig:ablate} (left) sweeps $\theta$: the most null-heavy relation,
\textsc{personHasCityOfDeath} (45\% empty), peaks at a \emph{lower} $\theta$,
while the others tolerate aggressive voting---arguing for per-relation
thresholds. Figure~\ref{fig:ablate} (right) varies the number of numeric
samples: median aggregation is non-monotonic on \textsc{hasArea} and actually
slightly \emph{hurts} \textsc{hasCapacity} (single sample $0.10$ vs.\ median-5
$0.09$). Decode variance is not the bottleneck---the gap is knowledge-bound; the
model's capacity guesses are the right order of magnitude but outside the 5\%
band (e.g.\ Spartan Stadium: predicted $37{,}000$, gold $75{,}005$).

\paragraph{\textsc{awardWonBy} is recall-capped.} The one relation we never beat the baseline on comfortably exposes a different limit. Gold sets average ${\sim}148$
recipients (max 641) but the 14B enumerates only ${\sim}11$ names---its outputs
are \emph{not} truncated (it closes the JSON early)---capping recall near

Parametric recall and willingness to enumerate bound this relation, where a larger in-budget model or multi-step decomposition would help most.

\section{Conclusion}
Every component of our system follows from a single metric analysis: abstention is valuable,
numeric recall is scarce, and scope grounding curbs over- and under-prediction.
With a single 14.7B open-weight model on commodity hardware it reaches $0.416$
relation-averaged macro-F\textsubscript{1} ($0.447$ micro), beating the official
baseline on five of six relations, and is fully reproducible from a cached
generation pass.

\section*{Limitations}
The voting threshold $\theta$ is swept on the same validation split it is
evaluated on, so per-relation optima are optimistic and not held-out; we report
no test numbers yet. Several margins are within plausible decoding noise:
\textsc{awardWonBy} has only 10 subjects, and we did not measure
run-to-run variance of the stochastic decoding ($N{=}3$, $n{=}5$), so
sub-$0.03$ deltas (e.g.\ the \textsc{personHasCityOfDeath} $+0.03$) are
indicative only. Being closed-book, the system inherits the base model's
coverage and recency limits and cannot recover facts it never stored, which caps
\textsc{awardWonBy} recall and rare-venue numeric accuracy; a larger in-budget
model (up to 32B) would likely help the numeric relations. Finally, the
abstention advantage is a property of this task's macro metric and the
empty-as-valid-answer setting, and may not transfer to single-answer or
micro-only settings.

\section*{Ethics and Generative-AI Declaration}
Closed-book KB construction surfaces facts from model parameters that may be
stale, biased, or hallucinated; predictions about people (e.g.\ place of death)
can be wrong and should not be treated as authoritative without verification. The
abstention mechanism partly mitigates this by emitting an empty answer rather
than a confident fabrication when the model is uncertain. The only generative-AI
component is the open-weight LM used for the predictions themselves, as the task
requires; no proprietary assistant was used to produce results.
