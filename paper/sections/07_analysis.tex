\section{Analysis}
\label{sec:analysis}
Because the headline 30B result is single-sample, we isolate the decode-time
levers on the 14B and 0.5B models, which we can sample freely; all ablations use
the same cached samples.

\paragraph{Abstention.}
Abstention rescues weak models and refines strong ones.
Table~\ref{tab:ablation} isolates it on the three null-heavy relations. On a
poorly-calibrated 0.5B model the effect is dramatic ($0.173\!\to\!0.363$ at the
deployed $\theta{=}0.5$, up to $0.372$ under the sweep): without voting it
over-answers and falls \emph{below} the empty baseline ($0.350$). The
14B is already above that baseline without voting ($0.652$), so voting adds less
($0.652\!\to\!0.666$) but still helps. Abstention buys precision: on
\textsc{personHasCityOfDeath} it moves $P{=}0.77\!\to\!0.81\!\to\!0.89$ as $\theta$
rises, trading a little recall. It suppresses wrong guesses, not correct answers.

\paragraph{Setting the threshold.}
If abstention drives the string relations, the natural next question is how to set
its threshold. Our deployed systems use a single fixed $\theta{=}0.5$ (a simple
majority of three samples); the sweep in Figure~\ref{fig:ablate} (left) is
diagnostic, and since it is run on the split we report on, its per-relation optima
are optimistic rather than values we tune back in. Still,
\textsc{personHasCityOfDeath} (45\% empty) peaks at a \emph{lower} $\theta$ while
the others tolerate aggressive voting, so a fixed majority leaves little on the
table. Figure~\ref{fig:ablate} (right) varies the number of numeric samples:
median aggregation is non-monotonic on \textsc{hasArea} and actually slightly
\emph{hurts} \textsc{hasCapacity} on the 14B (single sample $0.10$ vs.\ median-5
$0.09$). Decode variance is not the bottleneck; the gap is knowledge-bound: the
capacity guesses are the right order of magnitude but outside the 5\% band (e.g.\
Spartan Stadium: predicted $37{,}000$ vs.\ gold $75{,}005$), and even for the 30B
both numeric relations stay low ($0.17$, $0.33$).

\paragraph{The \textsc{awardWonBy} recall cap.}
The relation \textsc{awardWonBy}, which we beat the baseline on only narrowly, is
recall-capped, and this limit constrains both models. Gold sets average
${\sim}148$ recipients (max 641), but in the 14B ablation the model enumerates
only ${\sim}11$ names; its outputs are \emph{not} truncated, it closes the JSON
early, capping recall near $11/148\approx0.07$. The listed names are often
plausible but wrong ($P{=}0.36$). Parametric recall and a reluctance to enumerate
bound this relation; within a closed-book single model it is largely unsolved, and
a larger in-budget model or multi-step decomposition would help most.
